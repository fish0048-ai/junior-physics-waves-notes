# 思考習慣 → 講義篇寫脈絡（寫作指南）

本文件借鑑 Minerva 大學 **Habits of Mind／Foundational Concepts（HC）** 中，與「批判思考、实证發現」相關、且**國中理化講義能練到的**部分，對照本站既有的探究 HTML 槽位。**講義正文不出現 Minerva 名稱或 # 標籤**；HC 代號僅供老師／AI 對照公開說明（如 [Minerva HCs Intro PDF](https://www.minerva.edu/public/media/enrollment-center/Minerva-HCs-Intro.pdf)）。

與 [inquiry.md](inquiry.md) 的關係：inquiry 規定**結構與順序**；本文件規定**每格文案要練哪一種思考**。

## 目的與界線

- **要做的事**：讓「先提問，找證據，再主張」在每個槽位有具體自問句；習慣可重複練、可從 bridge／辨正思考看出學生是否只背定義。
- **不做的事**：不引入大學 rubric（1～5 分）、不寫談判／博弈／複雜系統高階 HC；不把課文改成哲學討論。
- **改寫邊界（硬性）**  
  - **凍結**：`sections/4-1.html`、`sections/4-2.html` — 不因本指南改 inquiry／辨正等篇寫；指南正例**不**以這兩節為改寫標的。  
  - **已改寫（inquiry 篇寫）**：4-3～4-5、第 5～6 章各節、實驗專區 `sections/lab-*.html`（lead／bridge／證據卡／主張開頭；**未刪**課文）。  
  - **仍凍結**：4-1、4-2 不套用本輪改寫。  
  - **樣板**：重寫時對齊 **4-3 之後**既有折射／透鏡／儀器／色散 inquiry 語氣，不回头統一成其他節口吻。

## 八項思考習慣（繁中名稱）

### 1. 問對問題

- **一句話**：本節只追**一個**生活現象，而且讀完這節**答得出來**。
- **Minerva 對照（文件用）**：#rightproblem  
- **HTML 槽位**：`section-hero` 副標、`#inquiry` 標題、`js/config-chN.js` 的 `sections[].ask`（須與 hero 同旨，見 inquiry.md）。  
- **寫作模板**  
  - 「（現象）為什麼會（可觀察結果）？」  
  - 避免：「認識折射定律」「學習透鏡成像」。  
- **正例（4-3）**：探究問題「泳池為什麼看起來比較淺？」— 學生沒讀課文也能先猜深淺。  
- **正例（4-5）**：「白光裡真的藏著彩虹嗎？」＋「顏色是自己發的還是被選擇的？」— 第二句收斂到反射／透射，仍是一節可答。  
- **反例**：「本節要認識凸透鏡和凹透鏡」（像目錄，不像探究）。

### 2. 先猜再驗

- **一句話**：先寫**說得通**的預測，對錯交給後面的圖和實驗。
- **Minerva 對照**：#plausibility  
- **HTML 槽位**：`inquiry-lead` 的「先預測：……？」→ `app.js`「我的預測」。  
- **寫作模板**  
  - 「先預測：（A 還是 B）？（若…應該看到…）？」  
  - 給**對立選項**（偏向法線／遠離法線；實像／虛像）。  
- **正例（4-3 lead）**：「光從空氣斜射入水，會偏向法線還遠離法線？」  
- **正例（4-4 lead）**：相機／眼睛 vs 顯微鏡「再放大給眼睛看」— 兩種模型先並列。  
- **反例**：「請認真閱讀下面重點」（沒有預測任務）。

### 3. 合理性檢查

- **一句話**：算數或背答案前，先問「這個數量級／方向合理嗎？」
- **Minerva 對照**：#estimation  
- **HTML 槽位**：`.extra`、計算卡、`#memo` 可點名「概算」；段考題解析語氣（exams 另案）。  
- **寫作模板**  
  - 「若答案是…，則（某現象）應該（更誇張／幾乎沒有）— 合理嗎？」  
  - 「差 10 dB 約 10 倍能量，70 對 50 差 20 → 約 \(10^2\) 倍。」  
- **正例（4-3 脈絡）**：全反射只在光密→光疏且入射角夠大— 若忽略介質方向，預測會與日常觀察矛盾。  
- **反例**：只列公式不問「代進去會不會比光速還快」。

### 4. 可檢驗預測

- **一句話**：問「若我說的對，**應該看見什麼**？」— 圖、動畫、實驗步驟要能對答案。
- **Minerva 對照**：#testability  
- **HTML 槽位**：`inquiry-ask`、`inquiry-path` 的 `<span>` 線索；實驗 `.lab-step` 前的 ask。  
- **寫作模板**  
  - 「若（假設）成立，（圖上／實驗中）應該（看到／量到）……？」  
  - 「垂直入射時，光路還會偏折嗎？」  
- **正例（4-3 p1 ask）**：垂直入射是否轉彎；斜射入水是「煞車靠法線」還是「油門離法線」。  
- **正例（4-3 透鏡站）**：「紙屏接得到的是實像還虛像？」— 直接對應動手實驗。  
- **反例**：「理解折射的重要性」（無觀察後果）。

### 5. 不只一種解釋

- **一句話**：至少列出**兩種**可能，再用下一站證據排除。
- **Minerva 對照**：#induction（多個概化）  
- **HTML 槽位**：`inquiry-lead`、必要時第一個 `inquiry-ask`。  
- **寫作模板**  
  - 「可能是 A，也可能是 B；下面用……來分辨。」  
  - 「像變大，是因為物近，還是屏近？」（若該節有兩變因）。  
- **正例（4-5 lead）**：紅玻璃「吸收紅光」vs「讓紅光通過、吸收其他」— 對立機制。  
- **正例（4-3 p2 ask）**：兩塊三稜鏡底對底像凸還是凹透鏡— 從形狀猜光路。  
- **反例**：lead 只丟一個結論式問句、沒有替代解釋。

### 6. 證據推論

- **一句話**：寫「**觀察到**…所以**暫時支持**…」，不要跳成課本定義標題。
- **Minerva 對照**：#induction（推論≠保證真）  
- **HTML 槽位**：`inquiry-bridge`「這一站的證據：」。  
- **寫作模板**  
  - 「這一站的證據：（現象）→（機制或規律）。下一站要問：（下一卡問題）。」  
  - 用「支持／符合」而非「證明宇宙真理」。  
- **正例（4-3 bridge p1）**：「折射因速率改變；快→慢偏向法線，垂直入射不偏折。」  
- **正例（4-3 bridge 末站）**：凸透鏡實像／放大虛像；凹透鏡永遠正立縮小虛像— 再接到章節問題。  
- **反例**：「這一站的證據：重點 2 折射定律。」（只重複標題）。

### 7. 找反例訂正

- **一句話**：用 ○× 或易錯句，找「一改成這樣，預測就錯」的反例。
- **Minerva 對照**：Evaluating claims（counterexamples）  
- **HTML 槽位**：`tag-orange` 辨正思考、`.wrong-note`；`#drill` 檢驗主張。  
- **寫作模板**  
  - 「若（錯誤說法），則應看到（荒謬結果）— 所以應訂正為……。」  
  - 辨正題：錯的打 ×＋**訂正**欄必填。  
- **正例（4-3 易錯脈絡）**：入射角是跟法線還是跟界面；虛像用延長線。  
- **反例**：辨正題只有 ○× 沒有訂正；易錯與辨正完全同一句话（重複堆疊）。

### 8. 清楚主張

- **一句話**：用**一句話**回答 hero 問題，含本節關鍵詞；不是抄 memo 條列。
- **Minerva 對照**：#thesis（簡化）  
- **HTML 槽位**：`#claim` 第一個 `<p>`（參考主張）；學生「我的主張」由 app 插入。  
- **寫作模板**  
  - 「（答 hero）因為（2～3 個本節核心詞）。」  
- **正例（4-3 方向）**：泳池變淺＝光折射＋視線折射；透鏡成像與物距像距關係。  
- **正例（4-4 方向）**：相機／眼睛 vs 顯微鏡兩段光學系統分工。  
- **反例**：「折射、凸透鏡、凹透鏡、焦點。」（名詞堆疊）。

## 一節內的習慣順序（與 inquiry 一致）

1. Hero — **問對問題**  
2. Lead — **先猜再驗**（＋**不只一種解釋**）  
3. Path — 每站 **可檢驗預測**  
4. 各站 Ask — **可檢驗預測**  
5. 課文 — 證據  
6. Bridge — **證據推論**  
7. Memo — **合理性檢查**、**別只找支持**  
8. Claim — **清楚主張**  
9. Drill — **找反例訂正**

## 各節 hero／ask 與習慣掛點（4-3～4-5、第 5～6 章）

改寫或新節時，先對這張表確認「問對問題」與 lead 是否對齊 config。

| 節 | 探究問題（hero／config ask） | 建議 lead 強化的習慣 | 建議 bridge／辨正強化的習慣 |
|----|------------------------------|----------------------|----------------------------|
| **4-3** | 泳池為什麼看起來比較淺？ | 先猜再驗（偏向法線）、可檢驗預測（垂直入射） | 證據推論（速率→折射）；透鏡站＋模型預測 |
| **4-4** | 顯微鏡、相機、眼睛同一套邏輯？ | 不只一種解釋（平面接像 vs 再放大） | 證據推論（兩段透鏡／調焦）；找反例（近視／遠視） |
| **4-5** | 白光藏彩虹？顏色從哪來？ | 不只一種解釋（吸收 vs 透過） | 證據推論（色散、選擇性吸收）；清楚主張（物色＝光剩什麼） |
| **5-1** | 用手摸得出準確冷熱嗎？溫度計量什麼？ | 先猜再驗（感覺 vs 讀數） | 合理性檢查（刻度、單位） |
| **5-2** | 熱量和溫度是同一件事嗎？ | 不只一種解釋（溫度升 vs 吸熱多） | 證據推論（比熱、公式 \(Q\)） |
| **5-3** | 加熱後只變熱還是狀態也變？ | 可檢驗預測（加熱曲線平台） | 模型預測（動畫 heating-curve） |
| **5-4** | 熱一定要碰到才傳？保溫瓶？ | 可檢驗預測（三種傳熱各舉例） | 證據推論（對流／輻射／傳導分工） |
| **6-1** | 怎樣才叫元素？金屬 vs 非金屬？ | 問對問題（分類標準） | 找反例（合金、同素異構若課文有） |
| **6-2** | 元素有沒有排隊規律？ | 先猜再驗（性質週期） | 證據推論（週期表位置→性質） |
| **6-3** | 最小單位是原子嗎？裡面還有什麼？ | 可檢驗預測（模型圖對現象） | 清楚主張（原子結構與電性） |
| **6-4** | 混合物、元素、化合物？化學式？ | 不只一種解釋（同質 vs 不同質） | 找反例訂正（化學式與分子數） |

第 3 章、**4-1／4-2** 已有 inquiry 鏈（見 inquiry.md 表）；**4-1／4-2 篇寫凍結**，僅供全站結構參考，不作思考習慣改寫標的。

## 與 `.extra`／`.gifted`／辨正分工

| 區塊 | 思考習慣重點 | 避免 |
|------|-------------|------|
| `.extra` | 合理性檢查、模型預測（一個生活應用） | 重複 bridge 整段 |
| `.gifted` | 模型預測、加深推論（仍不超綱） | 另起與 hero 無關的競賽題 |
| **辨正思考** | 找反例訂正（○×＋訂正） | 與 `.wrong-note` 同句複讀 |
| `.wrong-note` | 常見推論錯、別只找支持 | 塞成第二套辨正卷 |

## AI／老師用檢查表（新節或改 4-3+ 前）

- [ ] Hero 與 `config.*.ask` 同一探究問題（**問對問題**）
- [ ] `inquiry-lead` 含「先預測」且至少一組對立選項（**先猜再驗**）
- [ ] 每個 `#pN` 有 `inquiry-ask`，且能對圖／實驗回答（**可檢驗預測**）
- [ ] 至少一處 lead 或 ask 呈現兩種可能（**不只一種解釋**）
- [ ] 每站 `inquiry-bridge` 寫現象→結論，末站收束 hero（**證據推論**）
- [ ] `#claim` 參考主張是一句話答 hero（**清楚主張**）
- [ ] 辨正或易錯至少一題含「訂正／若…則…不合理」（**找反例訂正**）
- [ ] 計算或數量级內容在 extra 或 memo 有概算提示（**合理性檢查**，若該節有計算）
- [ ] 有 iframe 動畫時，extra 或 ask 提到改變因的預測（**模型預測**，若適用）
- [ ] **未改動** `sections/4-1.html`、`sections/4-2.html`（除非使用者另案解除凍結）
